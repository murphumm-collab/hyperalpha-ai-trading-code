# HyperAlpha AI Trading V1 验收清单

日期：2026-06-12

## V1 目标

V1 不是让 AI 直接实盘下单。

V1 的完成标准是：用户可以在本地/测试环境通过 AI Trading 页面完成标的选择、策略草案、自然语言调整、保存、审批、回测证据绑定、信号事件生成、拒绝/确认 handoff，并且只有通过安全检查的信号才会交给外部订单后端。

真实交易执行仍由 HyperAlpha 订单后端负责。

## 必须完成

- 多用户隔离：每个用户只能读取、调整、审批、归档、生成和 handoff 自己的 strategy spec / signal event / handoff attempt。
- 多会话 Agent：AI Trading strategy spec、signal event、handoff attempt 必须支持当前用户内的 `agent_session_id` 分区；agent session 本身可创建、重命名、更新压缩上下文和归档，并能生成包含策略、信号、handoff attempt 摘要的非敏感 session context packet，避免一个用户的多个策略会话混在一起。
- 上下文压缩边界：agent session context packet 必须返回 requested/effective/max strategy/signal/attempt limits 和 `summary_max_chars`，agent-session list/CRUD/nested audit payload 必须返回 `context_summary_chars` 和 `summary_max_chars`，压缩摘要必须受限并且 over-limit 请求必须被 API 拒绝，避免单用户长上下文拖垮共享 DeepSeek/Qwen 模型。
- 手工记忆安全：用户手工创建/编辑 agent session `context_summary` 时必须在写入前拒绝 API key、token、secret、private key、password、authorization 等敏感文本；自动生成的压缩摘要和既有 strategy-spec 兼容路径仍必须保持非敏感/脱敏。
- 会话名称安全：用户手工创建/重命名 agent session 时必须拒绝 API key、token、secret、private key、password、authorization 等敏感名称；历史/脏数据里的 agent-session name 只能以 `[redacted_sensitive_session_name]` 进入 API response、嵌套 spec/signal JSON 和 DeepSeek/Qwen model-adjust 上下文。
- 策略名称安全：用户保存 strategy spec 时必须拒绝 API key、token、secret、private key、password、authorization 等敏感展示名；历史/脏数据里的 strategy spec name 只能以 `[redacted_sensitive_strategy_name]` 或通用名称脱敏标记进入 spec list/detail、嵌套 spec JSON 和 agent-session context packet。
- 策略文本/source 安全：strategy draft / adjust / model-adjust instruction、stop-loss/take-profit rule、model source、record source 和 spec metadata source 是用户/API 可控输入，新写入或进入模型 prompt 前必须拒绝 API key、token、secret、private key、password、authorization 或订单后端 URL；历史/脏 strategy text/source 只能在 strategy detail、signal preview/event 和 gateway payload 中以脱敏占位符返回，不能传给模型或订单后端。
- 响应层记忆安全：历史/脏数据里的 `context_summary` / `agent_context_summary` 即使含有 API key、token、authorization、private key 等敏感字样，也只能留在 DB 审计中，不能从 strategy spec、signal event、handoff attempt、agent-session list/context 或嵌套 spec/signal JSON response 返回。
- 前端提示词安全：`Load context` 把 agent-session context packet 放入聊天输入前必须再次做本地脱敏；策略、回测、信号和 handoff review prompt 把 JSON packet 放入聊天输入前也必须做本地脱敏，不能把未来后端/插件回归带来的 API key、token、authorization 或敏感 summary/error/prompt 文本送入模型上下文。
- 模型上下文信任边界：DeepSeek/Qwen model-adjust 使用 agent-session context 时必须明确标记为不可信用户记忆、只能作为参考，不能覆盖 system prompt、signal-only/no-order、回测 gate、硬风控或用户确认要求。
- 模型输出安全：DeepSeek/Qwen model-adjust 返回的 `instruction`、`rationale`、`risk_notes` 在应用、返回或持久化前必须清洗，secret-like 文本只能以 `[redacted_sensitive_text]` 返回，直接下单/市价单/限价单等执行措辞只能以 `[direct_order_intent_ignored]` 返回；前端当前策略卡片、review packet 和 session history 必须显示非敏感、可读的安全提示，让用户知道模型输出曾被红线处理。
- 模型配置错误安全：AI Trading 的 Model setup 入口复用 Hyper AI LLM Config modal 时，保存/连接测试失败只能显示白名单状态或安全 fallback，不能把 provider response body、后端 raw `detail`、连接异常文本或 thrown message 渲染给 To C 用户。
- 标的物加载错误安全：AI Trading market selector 加载 watchlist、market-universe、available-symbols 时必须按来源降级；只有三个来源都不可用才显示安全错误，且不能把 raw backend detail、provider/upstream error、fetch exception 或 thrown message 渲染给 To C 用户。
- 标的物文本安全：AI Trading market-universe 后端、前端 selector、chat prompt 入口和 strategy-spec draft 入口都必须过滤 malformed/过长/secret-like symbol；HIP-3 `dex:symbol` 必须保留，过滤后的安全 symbol 才能进入 UI、模型上下文和 draft 请求。
- 市场标的：Hyperliquid Crypto Top 20/50 与 HIP-3 Top 20/50 可用于策略入口，HIP-3 `dex:symbol` 身份不能丢失。
- 策略草案：支持结构化 draft、validate、save、list、detail、approve、archive。
- 策略调整：支持本地受控自然语言 adjustment，也支持 DeepSeek/Qwen model-adjust 后进入同一个安全 parser。
- 安全边界：任何 strategy spec / signal candidate 都必须保持 `signal_only`、`not_an_order`、`ai_may_place_orders=false`、`order_backend_only=true`。
- 回测前置：signal event / handoff 必须绑定 handoff-ready backtest evidence；策略调整后旧 approval/backtest 必须失效。
- 回测证据安全：`backtest_id` / `run_id` / `source` / `notes` 是手工或后端绑定 evidence 的可控字段，新写入时必须拒绝 API key、token、secret、private key、password、authorization 或订单后端 URL；历史/脏 backtest evidence 只能在响应层以脱敏占位符返回，不能进入模型上下文、signal event response 或 gateway payload。
- 市场上下文安全：signal preview / signal event 的 `market_context.source`、`regime` 和数值字段是用户/API 可控输入，新写入时必须拒绝 API key、token、secret、private key、password、authorization 或订单后端 URL；历史/脏 market context 只能在 signal detail response 和 gateway payload 中以脱敏占位符或空数值返回，不能把敏感文本传给模型或订单后端。
- 信号审计：signal preview 必须持久化成 current-user signal event，支持 detail/list/reject；reject `reason` 是用户可控字段，写入 signal audit 前必须拒绝 API key、token、secret、private key、password、authorization 或订单后端 URL，历史/脏 `review.reason` 只能在响应层以脱敏占位符返回。
- 订单后端 handoff：默认 disabled；启用后也必须要求用户确认、未过期、信号身份一致、action/symbol 一致、回测合格、payload 契约稳定。
- handoff 用户确认安全：`confirmation_source` 是用户可控字段，写入 attempt audit 或 gateway payload 前必须拒绝 API key、token、secret、private key、password、authorization 或订单后端 URL；历史/脏 `user_confirmation.source` 只能在响应层以脱敏占位符返回。
- 脱敏：API response、AI stream polling/status error、AI stream error/interrupted chunk、gateway payload、handoff attempt、handoff `error_message`、handoff `confirmation_source` / `user_confirmation.source`、signal reject `reason` / `review.reason`、strategy spec text/source、backtest evidence `backtest_id` / `run_id` / `source` / `notes`、signal `market_context`、production handoff/readiness URL host/port/parse-error 报告都不能泄露 API key、token、secret、private key、authorization 或真实订单后端 URL；malformed URL / malformed URL port 必须 fail closed，且不能回显 invalid URL/port 原文或 parser exception。
- 前端：`/app/ai-trading` 页面必须支持完整操作流，按钮状态必须以后端 preflight 为准。
- 运营 readiness：管理员必须能通过只读、无网络、无提交的 production readiness 报告看到 Auth/JWKS、订单后端 handoff、AI stream、硬风控、模型 key policy、handoff audit 和 agent-session context budget 的上线 blocker/warning；管理员还必须能读取 production evidence explain 清单来确认真实上线前缺哪些外部验收材料；普通用户不能访问；CLI production readiness 可显式打开 DB audit 以覆盖持久化 handoff/session 风险。
- 生产操作员预检：必须有一个只读 CLI 聚合 Git governance、本地 runtime、production readiness 和 completion/evidence 边界；默认缺真实生产 env / 外部 evidence 时必须保持 blocked，且不能调用模型、交易所、订单后端或 GitHub，也不能输出 env secret 值；实盘切换前如果 worktree 有未提交改动必须 fail closed，只能输出 dirty count/action，不能输出文件名、patch 或敏感路径；最终 JSON 还必须递归清洗 secret-like 字符串，包括带 secret 的外部 evidence 文件路径。
- 文档：status、memory、gateway contract、V1 checklist 必须保持最新。
- Git：只在 `codex/ai-agent-multitenant-foundation` 分支开发；GitHub 上传已同步到 origin/codex/ai-agent-multitenant-foundation；不合并。
